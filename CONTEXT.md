# Context

Terms used in this codebase.

- **Card catalogue** (`cards.jac`): the one module that looks cards up, resolves card names and keeps `Card` nodes as a cache of the SQLite catalogue; `RefreshCards` updates that cache, run as the guest at start (`refresh_cards` in `graph_runner.jac`) when the catalogue is a different build from the one last refreshed against. Only it calls `catalog.store`.
- **Deck holdings**: the cards a deck holds, as `Holds` edges (a count in one zone, plus entry metadata). They change only through `change_holding` (one card in one zone, set or add) or `replace_holdings` (the whole list) in `decks.jac`, which check the zone, count and reason and log each count change as a `ChangeNote`.
- **Commander**: the format where a deck is the commander zone plus the main deck, exactly 100 cards, singleton, led by one eligible commander. Its rules are `check_commander` in `legality.jac`; the commander zone helpers and eligibility live in `commander.jac`.
- **Partner pair**: two commanders that may lead one Commander deck together (Partner, Partner with, Partner—quality, Choose a Background with a Background, Doctor's companion with a Time Lord Doctor). `pair_problem` in `commander.jac` returns why a pair is illegal, or `""`.
- **Game Changer**: a card on Wizards' Commander Game Changers list, carried as `CardLine.game_changer`. `game_changers(lines)` in `commander.jac` collects the distinct ones in the commander, companion and main zones; `DeckView.game_changers` holds them for Commander decks only.
- **Bracket hint**: the bracket a deck's Game Changer count suggests (0 is 1–2, 1 to 3 is 3, 4+ is 4+), from Game Changers only; not a full bracket rating. Always labelled as a hint.
- **Zone**: where in a deck a card is held: one of `ZONES` in `zones.jac` (commander, companion, main, sideboard, maybeboard), each with its heading in `ZONE_TITLES`; `decks.jac` re-exports them (the web page must import them from `zones`, since importing from `decks` pulls the whole module into the client bundle). Constructed formats count main and sideboard, and Commander counts the commander zone and main deck (checking the companion too).
- **Edit walker** (`EditDeck`, `decks.jac`): the one walker for what a user does to one of their decks, and one commit per call: an optional new name, an optional format and a batch of changes, each a `set` (the default) or an `add` of a count in a zone, with a reason. Every change goes through `change_holding`; a refused change is listed under the view's `rejected` and the rest applied, while a refused name or format refuses the call before anything is written. MCP `deck_edit`, `deck_create` (through `CreateDeck`'s `changes`, which makes and fills the deck in one walker), the web page's add, set and remove controls (with `WEB_EDIT_REASON`) and the card search view's Add all call it.
- **Change note**: one logged change to a deck's holdings (card, zone, count before and after, and the reason). Kept on the `Deck` as its history. A note about the whole deck (copied, renamed) has no card, zone or counts, only the reason (`deck_note` in `decks.jac`). A change to a **Collection** logs the same note with no zone, kept on the `Collection`.
- **Delete walker** (`DeleteDeck`, `decks.jac`): the owner's one way to remove a deck, an `OWN`, page-callable entry of the deck operations table, so another user's deck is refused with `not-your-deck` and an unknown id with `no-such-deck` like any change. It deletes the `Deck` node with its `Holds` edges and its history, and reports a `DeckDeleted` (id and name); the shared `Card` nodes, the owner's collection, their other decks and copies made from it stay. The web page offers it to the owner only (the deck view's `mine`), behind an in-page confirmation, and returns to the deck list; MCP `deck_delete` calls it and tells the agent to confirm with the user first.
- **Collection** (`collection.jac`): the cards a user has, as a count per oracle card (ADR 0005: stored per (card, printing) with the printing blank). A `Collection` node hangs off the user's own root and its counts are `Owns` edges to the shared `Card`; it keeps its change notes as its history. `set_count` is its one writer: an absolute count, 0 takes the card out, a reason required, one change note. `ChangeCollection` (mode `add`, `remove` or `set`, always worked out against the current count) and `GetCollection` are walkers in the deck operations table (`OWN`, page-callable); removing more copies than held is refused with `refused-change`, saying how many are held, and changes nothing. `ImportCollection` adds a pasted list in any format deck import reads (`resolve_list`): zones are ignored, repeats summed, the totals added to the current counts through `set_count` with the reason "imported", never lowering a count; names that resolve to no card come back as `unresolved` and the rest still go in. MCP `collection_get`, `collection_change` and `collection_import`, and the web page's own "My collection" view (`collection_page.jac`, apart from the deck views, with its paste box), call them. Editing a deck never changes it, and a card a deck uses can be removed from it. **Reading another user's collection** and **User handle** are defined below. `collection_views.jac` holds what the page imports (the view and the modes), as `zones.jac` does for decks.
- **Deck view** (`DeckView`, `deck_view` in `decks.jac`): the one read of a deck that every deck walker reports: its card lines, totals, legality, recent history, main-deck mana analysis (mana profile and curve) and `mine`, whether the caller owns the deck. A client gets the whole picture from the edit's own response; MCP `deck_analyze` is just the `mana` and `curve` part of it, plus the name, format and main total its chart view needs.
- **Missing cards**: what a deck needs that its owner's collection lacks: per oracle card, the copies across the played zones (`PLAYED_ZONES` in `zones.jac`: every zone but the maybeboard) minus the owner's count, never below zero (`missing_cards` in `card_lines.jac`). Each deck is measured on its own against the whole collection. `DeckView.missing` lists them and every `CardLine.collection_count` is the owner's count for it (maybeboard lines too). The runner fills both in on the root the walker ran on (`stamp_collection`, `collection.jac`), so a deck another user reads is always measured against its owner's collection.
- **Sleeveable**: a deck you can sleeve up and play: it is not **unfinished**, it passes its format's legality check, and it has no **missing cards** (`DeckView.sleeveable`). An empty or half-built deck is never sleeveable, even though nothing in it is missing. (Until the redefinition lands, the code still sets it from missing cards alone, `collection.jac`.) _Avoid_: ready, complete.
- **Unfinished**: a deck whose played zones (`PLAYED_ZONES`) hold fewer cards than its format needs: 60 for constructed formats, 100 for Commander. It says nothing about ownership: an unfinished deck can have no missing cards, and a finished one can have many. _Avoid_: incomplete (it sounds like missing cards).
- **Quest list** (`quest_list.jac`): every card a user's decks need that their collection does not have, worked out on read and never stored. Per oracle card: the largest count any one of the user's decks needs across the played zones (`PLAYED_ZONES`, so no maybeboard) minus the collection's count, kept when above zero; each line carries the card, the number still needed and each deck that needs it with how many it needs. A deck's own part of it is its **missing cards**. `GetQuestList` reads the caller's and `GetOtherQuestList` (a `USER` entry, by handle, read-only) another user's; both take `export` to add the list as plain text through the text line-list renderer (`3 Lightning Bolt`). `GotQuest` is "got N": the collection's writer (`change_count`) adds N copies with the reason "got from the quest list", so getting fewer than needed reduces the line. MCP `quest_list` and the web views `quest_list_page.jac` and `others_quest_lists_page.jac` call them. _Avoid_: wishlist, to-get list, shopping list.
- **Card line** (`CardLine`, `card_lines.jac`): one card in one zone of a deck, with its count, entry metadata and catalogue facts. `card_lines(deck)` in `decks.jac` is the one place lines are built from the graph; legality (`check_lines`), the mana profile and the curve are pure functions over a deck's lines, and `DeckView.cards` is that list. It holds the one definition of a **land** (`is_land`: the front face is a land, so a spell // land double-faced card is a spell) and of the **main deck** (`main_deck`: the main zone).
- **Deck operations** (`deck_operations.jac`): the one table of what the app can do with decks, and `perform(caller, operation)`, the one call both edges make. Each entry names a walker and says how it runs: on the caller's own root (`OWN`), on the deck owner's root for a read-only walker (`OWNER`, **Reading another user's deck**), as a runner flow across users' roots (`FLOW`: listing other users' decks, listing users, **Copy**), or read-only on a named user's root (`USER`: **Reading another user's collection**); and whether the web page may call it. The front door's table of page-callable walkers is derived from it (`page_walkers`), and the MCP deck tools call `perform`. Adding a deck action is the walker plus one entry. A **Walker error** is `perform`'s failure result.
- **Walker error** (`WalkerError`, `walker_errors.jac`): why a walker failed, as its one and only report: a stable `code` (e.g. `no-such-deck`, `not-your-deck`, `unknown-format`, `unknown-list-format`, `blank-name`, `no-import`) and a `message` to show as is. The runner gives `try-again` when a call still meets another writer after its re-runs, and `internal-error` when Jac refuses a write the app's own checks allowed; no runner entry or `perform` call raises `CallFailed` (the runner's own exception for them): each returns the walker error instead, as a walker's one report or, for `call_function` and `list_other_decks`, in place of the value. `DeckAction` reports `no-such-deck` for an id that names no deck and `not-your-deck` for another user's deck, for every deck walker. Every MCP tool fails the one way, through `adapted` in `mcp_tools.jac`: `is_error` with the message as its text and `{"error", "code"}` as its structured content (`outcome` and `ask` raise `ToolFailure` with the walker error, so a tool never builds its own error shape). The web reads every failure with `failureMessage` (`walker_failure.jac`): a walker's reports as they come, a function call's result as `[result]`. A call the front door refuses before or instead of running it (a 429, `try-again`, the internal error) reaches the web page as one such WalkerError, a walker's report and a function's result (`refusedAsReport` in `session_bar.jac`), and each MCP Apps view shows it as one line with a retry (`ui/refusal.html`).
- **Locked** / **Unlocked**: the two states of the web app's lock on what the user owns (their decks and their collection). A page opens locked: read-only, with no count controls. Unlocking it turns on the count controls and, on a deck, makes its search cover the whole catalogue; every change still saves at once through the usual writer, with its change note. Leaving the page, switching tab or switching Mine/Others locks it again. Other users' decks and collections have no lock: they are always read-only. _Avoid_: edit mode, editing (nothing waits to be saved).
- **Admin**: the person who runs the hosted instance and keeps the invite list. Not a role inside the app: the admin acts from outside it. _Avoid_: owner (that is the user a deck belongs to).
- **User**: an invited person who has signed in with Google. _Avoid_: account, member.
- **Guest**: the app's own identity, not a person. It owns what every user shares: the cards and the formats. Work the app does on cards for no particular user is done as the guest. No user signs in as it and no deck belongs to it. _Avoid_: anonymous user, shared user.
- **Local user**: the one stand-in user every call runs as when the app runs on a developer's machine, where there is no sign-in. It owns the decks made there. _Avoid_: guest, dev user.
- **Owner**: the user a deck belongs to: the one who created it. Every deck has exactly one owner and it never changes. Every user can see every deck, but only the owner can change or delete it. _Avoid_: admin, creator, private (no deck is hidden from other users).
- **Copy**: a new deck made from another user's deck as it stands at that moment, owned by whoever copied it. It carries the cards and their entry metadata, starts its own history, and has no tie to the original afterwards. Named "<name> (copy)", with one history line saying it was copied. `copy_deck` in `graph_runner.jac` makes it (the `CopyOtherDeck` entry of **Deck operations**): a read as the owner (`CopySource`), then a create as the copier (`CopyDeck`). _Avoid_: fork, share.
- **Reading another user's deck**: `perform` (**Deck operations**) runs a read-only deck walker (an `OWNER` entry of its table) through `run_read` (`graph_runner.jac`) on the deck's owner's root, for any signed-in caller, after the app has decided the read is allowed. No grants, no `Holds` edges, no access for the caller. MCP `deck_get`, `deck_show`, `deck_analyze`, `card_search` and `deck_export` read this way; `deck_browse` (`list_other_decks`) lists other users' decks with each owner's display name ("Unknown user" when none is stored) and `deck_copy` copies one. The web page does the same through the `ListOtherDecks` and `CopyOtherDeck` walkers, which are `FLOW` entries of the table: it shows other users' decks in their own read-only section, and opens one without the controls that change it, with a Copy action. The deck view's `mine` says whether the caller owns the deck (the runner sets it on the way out, `stamp_ownership`): the card search view offers its Add buttons, and the web page its change controls, only then.
- **User handle**: the opaque name of a user wherever one user names another: their root id without dashes, never an email address.
- **Reading another user's collection**: users are named by an opaque **user handle** (their root id without dashes, never an email address). `ListUsers` (a `FLOW` entry, `list_users` in `graph_runner.jac`) lists the other users, never the caller, each with handle and display name (`UNKNOWN_USER` when none is stored); `GetOtherCollection` is a `USER` entry that `perform` runs through `run_read_user` on that user's root, under the rules of **Reading another user's deck**: no grants, no edges, no access for the caller. An unknown handle answers `no-such-user`; `ChangeCollection` with a `handle` is refused with `not-your-collection`. MCP `user_list` and `collection_browse`, and the web page's "Other users' collections" view (`others_collections_page.jac`, read-only, apart from "My collection") call them.
- **Invite list**: the email addresses allowed to become users. An address is matched once, exactly, at first sign-in, and the user is bound to that Google account from then on.
- **Front door**: the one part of the hosted instance that answers requests from the internet. It checks who is asking before anything else happens, and refuses anyone not signed in, apart from the few paths needed to sign in. Both the web UI and the claude.ai connector come through it. In code it is `front_door.jac`, started by `mcp_server.jac`, and three modules sit behind it: the **gatekeeper** (`gatekeeper.jac`: credentials, browser sessions and rate limits, yielding the `Caller` of every request it lets through, and the only place that works out who is asking), the deck-call endpoint (`deck_call.jac`: takes a `Caller` and calls `perform`, no sign-in work) and the upstream child (`upstream_child.jac`: starts, stops and watches Jac's server); identity reaches the runner as an argument only; Jac's own server runs only as its child on `127.0.0.1` and hands out the web page and its static files, and the front door runs the page's deck calls itself, through the runner. Browsers sign in through the gatekeeper with AuthKit (`browser_session.jac`) and keep one cookie holding WorkOS's sealed session; a request with no session gets a sign-in redirect (a page) or a 401 (anything else). In local mode it takes the same path with the local user as the caller. _Avoid_: proxy, gateway.
- **Spec**: a GitHub issue that describes one whole piece of work and has tickets as its sub-issues, titled `Spec: …` (e.g. #123). Nobody works on a spec directly: it is done when its tickets are. _Avoid_: epic, parent ticket, story.
- **Stack**: the tickets of one spec as stacked PRs (`gh stack`). The bottom PR targets `main`, each ticket after it targets the branch of the ticket below, and PRs merge bottom-up. A ticket with no spec is a plain PR into `main`. _Avoid_: chain, queue (the merge queue is something else).
- **Ticket**: an issue with no sub-issues, small enough for one worker to finish in one PR. When it belongs to a spec, it is a sub-issue of that spec and starts its body with `## Parent` (e.g. #132 under #123). The ticket loop picks only tickets, never specs or maps. _Avoid_: sub-ticket, sub-issue (that is GitHub's link, not the kind of work), task.
