# Context

Terms used in this codebase.

- **Card catalogue** (`cards.jac`): the one module that looks cards up, resolves card names and keeps `Card` nodes as a cache of the SQLite catalogue; `RefreshCards` updates that cache, run as the guest at start (`refresh_cards` in `graph_runner.jac`) when the catalogue is a different build from the one last refreshed against. Only it calls `catalog.store`.
- **Deck holdings**: the cards a deck holds, as `Holds` edges (a count in one zone, plus entry metadata). They change only through `change_holding` (one card in one zone) or `replace_holdings` (the whole list) in `decks.jac`, which check the zone, count and reason and log each count change as a `ChangeNote`.
- **Commander**: the format where a deck is the commander zone plus the main deck, exactly 100 cards, singleton, led by one eligible commander. Its rules are `check_commander` in `legality.jac`; the commander zone helpers and eligibility live in `commander.jac`.
- **Partner pair**: two commanders that may lead one Commander deck together (Partner, Partner with, Partner—quality, Choose a Background with a Background, Doctor's companion with a Time Lord Doctor). `pair_problem` in `commander.jac` returns why a pair is illegal, or `""`.
- **Game Changer**: a card on Wizards' Commander Game Changers list, carried as `CardLine.game_changer`. `game_changers(lines)` in `commander.jac` collects the distinct ones in the commander, companion and main zones; `DeckView.game_changers` holds them for Commander decks only.
- **Bracket hint**: the bracket a deck's Game Changer count suggests (0 is 1–2, 1 to 3 is 3, 4+ is 4+), from Game Changers only; not a full bracket rating. Always labelled as a hint.
- **Zone**: where in a deck a card is held: one of `ZONES` in `decks.jac` (commander, companion, main, sideboard, maybeboard). Constructed formats count main and sideboard, and Commander counts the commander zone and main deck (checking the companion too).
- **Change note**: one logged change to a deck's holdings (card, zone, count before and after, and the reason). Kept on the `Deck` as its history.
- **Deck view** (`DeckView`, `deck_view` in `decks.jac`): the one read of a deck that every deck walker reports: its card lines, totals, legality, recent history and main-deck mana analysis (mana profile and curve). A client gets the whole picture from the edit's own response; MCP `deck_analyze` is just the `mana` and `curve` part of it, plus the name, format and main total its chart view needs.
- **Card line** (`CardLine`, `card_lines.jac`): one card in one zone of a deck, with its count, entry metadata and catalogue facts. `card_lines(deck)` in `decks.jac` is the one place lines are built from the graph; legality (`check_lines`), the mana profile and the curve are pure functions over a deck's lines, and `DeckView.cards` is that list. It holds the one definition of a **land** (`is_land`: the front face is a land, so a spell // land double-faced card is a spell) and of the **main deck** (`main_deck`: the main zone).
- **Walker error** (`WalkerError`, `walker_errors.jac`): why a walker failed, as its one and only report: a stable `code` (e.g. `no-such-deck`, `not-your-deck`, `unknown-format`, `unknown-list-format`, `no-import`, `refused-change`) and a `message` to show as is. The runner gives `try-again` when a call still meets another writer after its re-runs, and `internal-error` when Jac refuses a write the app's own checks allowed. `DeckAction` reports `no-such-deck` for an id that names no deck and `not-your-deck` for another user's deck, for every deck walker; MCP tools pass it on as `{"error", "code"}` (`outcome` in `mcp_server.jac`) and the web reads it with `failureMessage` (`walker_failure.jac`). A call the front door refuses before or instead of running it (a 429, `try-again`, the internal error) reaches the web page as one such report (`refusedAsReport` in `session_bar.jac`), and each MCP Apps view shows it as one line with a retry (`ui/refusal.html`).
- **Admin**: the person who runs the hosted instance and keeps the invite list. Not a role inside the app: the admin acts from outside it. _Avoid_: owner (that is the user a deck belongs to).
- **User**: an invited person who has signed in with Google. _Avoid_: account, member.
- **Guest**: the app's own identity, not a person. It owns what every user shares: the cards and the formats. Work the app does on cards for no particular user is done as the guest. No user signs in as it and no deck belongs to it. _Avoid_: anonymous user, shared user.
- **Local user**: the one stand-in user every call runs as when the app runs on a developer's machine, where there is no sign-in. It owns the decks made there. _Avoid_: guest, dev user.
- **Owner**: the user a deck belongs to: the one who created it. Every deck has exactly one owner and it never changes. Every user can see every deck, but only the owner can change or delete it. _Avoid_: admin, creator, private (no deck is hidden from other users).
- **Copy**: a new deck made from another user's deck as it stands at that moment, owned by whoever copied it. It carries the cards and their entry metadata, starts its own history, and has no tie to the original afterwards. Named "<name> (copy)", with one history line saying it was copied. `copy_deck` in `graph_runner.jac` makes it: a read as the owner (`CopySource`), then a create as the copier (`CopyDeck`). _Avoid_: fork, share.
- **Reading another user's deck**: `run_read` (`graph_runner.jac`) runs a read-only deck walker on the deck's owner's root, for any signed-in caller, after the app has decided the read is allowed. No grants, no `Holds` edges, no access for the caller. MCP `deck_get`, `deck_show`, `deck_analyze`, `card_search` and `deck_export` read this way; `deck_browse` (`list_other_decks`) lists other users' decks with each owner's display name ("Unknown user" when none is stored) and `deck_copy` copies one. The web page does the same through the `ListOtherDecks` and `CopyOtherDeck` walkers, which the front door answers from those runner calls: it shows other users' decks in their own read-only section, and opens one without the controls that change it, with a Copy action. `owns_deck` tells a view whether to offer its change controls (the card search view's Add buttons).
- **Invite list**: the email addresses allowed to become users. An address is matched once, exactly, at first sign-in, and the user is bound to that Google account from then on.
- **Front door**: the one part of the hosted instance that answers requests from the internet. It checks who is asking before anything else happens, and refuses anyone not signed in, apart from the few paths needed to sign in. Both the web UI and the claude.ai connector come through it. In code it is `front_door.jac`, started by `mcp_server.jac`; Jac's own server runs only as its child on `127.0.0.1` and hands out the web page and its static files, and the front door runs the page's deck calls itself, through the runner. Browsers sign in through it with AuthKit (`browser_session.jac`) and keep one cookie holding WorkOS's sealed session; a request with no session gets a sign-in redirect (a page) or a 401 (anything else). In local mode it takes the same path with the local user as the caller. _Avoid_: proxy, gateway.
- **Spec**: a GitHub issue that describes one whole piece of work and has tickets as its sub-issues, titled `Spec: …` (e.g. #123). Nobody works on a spec directly: it is done when its tickets are. _Avoid_: epic, parent ticket, story.
- **Ticket**: an issue with no sub-issues, small enough for one worker to finish in one PR. When it belongs to a spec, it is a sub-issue of that spec and starts its body with `## Parent` (e.g. #132 under #123). `scripts/ready-tickets.sh` picks only tickets, never specs or maps. _Avoid_: sub-ticket, sub-issue (that is GitHub's link, not the kind of work), task.
